# 安装图示

一页看懂：装了哪些键、对应哪种右键场景、一次点击怎么走到「文件进列表」。

## 1. 五个 base 对应五种右键场景

Shell 的「扩展菜单」是按**被点的对象类型**分开挂的，所以同一个扩展要挂五个位置：

```
                        ┌─────────────────────────────┐
  右键「一个文件」      │  HKLM\Software\Classes\*     │
  （或一批选中文件）    │    \shellex\                  │
                        │      ContextMenuHandlers\     │
                        │        xToolsEx64             │
                        └─────────────────────────────┘

                        ┌─────────────────────────────┐
  右键「一个文件夹」    │  ...\Classes\Directory       │  ← 图标态
  （文件管理器里的）    │  ...\Classes\Folder          │  ← 通用态（与上重复，可能插两次）
                        └─────────────────────────────┘

                        ┌─────────────────────────────┐
  右键「一个驱动器」    │  ...\Classes\Drive           │
  （C:、D: 这种）       └─────────────────────────────┘

                        ┌─────────────────────────────┐
  在文件夹「空白处」    │  ...\Classes\Directory       │
  右键                  │            \Background       │
                        └─────────────────────────────┘
```

| base 键 | 什么场景下出现 | 拿到什么 |
|---|---|---|
| `*` | 任意文件（含多选） | `CF_HDROP` 里的每个文件路径 |
| `Directory` | 文件夹（资源管理器图标态） | `CF_HDROP` 里的文件夹路径 |
| `Folder` | 文件夹（通用 shell 视角） | 同上，与 `Directory` 重叠 |
| `Drive` | 驱动器根，如 `D:\` | 驱动器根路径，如 `D:\` |
| `Directory\Background` | 文件夹内的空白处 | `CF_HDROP` 通常为空，改用 `IShellExtInit` 的 pidl 反查目录 |

> `Folder` 和 `Directory` 在多数系统上会同时命中，表现为**菜单出现两次**。如果只想显示一次，
> 把 `Folder` 那一处 handler 键删掉即可（它是为兼容某些老式宿主留的）。

## 2. 一个 base 下的完整链条

以 `*`（右键文件）为例，三级跳：

```
HKLM\Software\Classes\*\shellex\ContextMenuHandlers\xToolsEx64
   └─ (默认值) = "{9E7B4C21-3A55-4F0E-8D1A-2B3C4D5E6F70}"      ← 只有 CLSID，没有文字

HKLM\Software\Classes\CLSID\{9E7B4C21-3A55-4F0E-8D1A-2B3C4D5E6F70}
   ├─ (默认值) = "拖把更名器 64 位右键扩展"                     ← 内部描述
   └─ InprocServer32
        ├─ (默认值)       = "D:\...\xToolsEx64.dll"             ← DLL 真实路径
        └─ ThreadingModel = "Apartment"
```

Shell 的动作顺序：枚举 `ContextMenuHandlers` 的子键 → 读默认值拿 CLSID → `CoCreateInstance`
→ 加载 DLL → 调 `IShellExtInit::Initialize`（给 pidl + `IDataObject`）→ `QueryContextMenu` 插菜单
→ 用户点击 → `InvokeCommand`。

## 3. 四个视图：为什么 64 位系统要写两套

「注册表视图」不是说有四个键，而是同一段路径在两个位宽下**看到的不是同一份数据**：

```
                      64 位进程看到的                 32 位进程看到的
                    ┌──────────────────────┐      ┌──────────────────────┐
HKLM\Software\      │  Classes\...         │      │  Wow6432Node\        │
Classes             │  （64 位视图）        │      │    Classes\...       │
                    │  KEY_WOW64_64KEY     │      │  KEY_WOW64_32KEY     │
                    └──────────────────────┘      └──────────────────────┘
```

| 视图 | 谁在读 | 写不写 |
|---|---|---|
| `HKLM` + 64 位 | 64 位 Explorer、Directory Opus 13、Everything 1.5 | 写 |
| `HKLM` + 32 位 | Everything 1.4、其它 32 位宿主 | 仅当同目录有 `xToolsEx86.dll` 才写 |
| `HKCU` + 64 位 | 每用户类注册（优先级高于 HKLM） | 不写，但**安装时清理残留** |
| `HKCU` + 32 位 | 同上 | 不写，但清理残留 |

两个要点：

- **写 `HKLM` 而不是 `HKCU`**：Everything、Directory Opus 只读机器级注册。只写 `HKCU` 的话在它们里看不到菜单。
  代价是安装必须提权，这是必要的。

## 4. 安装脚本做了什么

```
安装.bat
  └─ install-xToolsEx64.ps1   （UAC 自提升）
       1. 校验 xToolsEx64.dll 是 PE32+ / 0x8664（别拿 32 位的装错位置）
       2. 清理 HKCU 下的旧注册残留（两套视图）
       3. regsvr32 /s xToolsEx64.dll          → DllRegisterServer 写 HKLM 两套视图
       4. 若同目录有 xToolsEx86.dll → regsvr32 /s xToolsEx86.dll
       5. 写 HKCU\Software\xTools\ShellEx64 的 MenuText / HelpText / ExePath
       6. 读回 LastWarn，非空就黄色警告（注册过程中的非致命问题）
       7. 询问是否重启 explorer.exe
```

卸载是镜像操作：两次 `regsvr32 /u` → 删 5 处 handler 键 → 删 CLSID → 删 `HKCU` 配置。

## 5. 手工核对（脚本出问题时的备用套路）

```bat
:: 1) 菜单项挂在没挂上（五个 base 各看一次）
reg query "HKLM\Software\Classes\*\shellex\ContextMenuHandlers\xToolsEx64"
reg query "HKLM\Software\Classes\Directory\shellex\ContextMenuHandlers\xToolsEx64"
reg query "HKLM\Software\Classes\Folder\shellex\ContextMenuHandlers\xToolsEx64"
reg query "HKLM\Software\Classes\Drive\shellex\ContextMenuHandlers\xToolsEx64"
reg query "HKLM\Software\Classes\Directory\Background\shellex\ContextMenuHandlers\xToolsEx64"

:: 2) CLSID 指向哪个 DLL（路径对不对、是不是旧副本）
reg query "HKLM\Software\Classes\CLSID\{9E7B4C21-3A55-4F0E-8D1A-2B3C4D5E6F70}\InprocServer32"

:: 3) 32 位视图（给 Everything 1.4 之类）
reg query "HKLM\Software\Classes\Wow6432Node\CLSID\{9E7B4C21-3A55-4F0E-8D1A-2B3C4D5E6F70}\InprocServer32"

:: 4) 有没有 HKCU 残留盖住 HKLM
reg query "HKCU\Software\Classes\*\shellex\ContextMenuHandlers\xToolsEx64"
```

> 注意第 3 条：**手工查询**用 `Wow6432Node` 这个字面路径是对的（`reg.exe` 是 64 位程序，
> 直接查 32 位物理位置）。但**代码里**不能这么拼——要用 `KEY_WOW64_32KEY` 标志，
> 让系统去重定向。两者别搞混。

## 6. 菜单不出现？按这个顺序查

```
菜单不出现
├─ 系统是 32 位？ ─────────── 是 → 用原版 xToolsEx.dll，本扩展不适用
├─ 宿主是 64 位？ ─────────── 否 → Everything 1.4 之类用原版 xToolsEx.dll
├─ DLL 路径对不对？ ───────── 查 InprocServer32，确认不是被删/被改名的旧副本
├─ HKCU 有没有残留？ ──────── 有 → 清掉再重装
├─ 宿主是 Directory Opus？ ── 是 → 它默认不显示第三方 shell 扩展，需在设置里开启
├─ Explorer 缓存？ ────────── 重启 explorer.exe 或注销
└─ 菜单有、图标没有 ──────── 见 README「菜单有了但没图标」
```
